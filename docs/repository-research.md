# Repository research and packaging decision

Checked September 20, 2026, before restructuring this repository. These are design observations from source repositories, not claims that another project's architecture is universally best.

| Source | Useful pattern | Applied here |
| --- | --- | --- |
| [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) and its [get-started guide](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/get-started/index.md) | A short install command, a complete first example, and examples exercised by tests. | The root README starts with installation and a complete route example; `examples/basic.py` is a standalone script. |
| [OpenAI Agents Python](https://github.com/openai/openai-agents-python) and its [quickstart](https://github.com/openai/openai-agents-python/blob/main/docs/quickstart.md) | Small public primitives, then separate runnable examples and deeper reference docs. | The public import is `JevToolRouter, Tool`; detailed policy and lab documentation sit outside the first-use path. |
| [Pydantic AI](https://github.com/pydantic/pydantic-ai/blob/main/pyproject.toml) and its [contribution guide](https://github.com/pydantic/pydantic-ai/blob/main/docs/contributing.md) | Optional capabilities have explicit dependencies, and contributors get one documented local check path. | OpenRouter and Typer are in the `lab` extra, and `CONTRIBUTING.md` lists one set of checks. |
| [Vercel AI SDK](https://github.com/vercel/ai/blob/main/packages/ai/README.md) and its [contribution guide](https://github.com/vercel/ai/blob/main/CONTRIBUTING.md) | The installable package and contribution workflow are clear even in a larger repository. | The root describes the product, while `jev_router.lab` and `experiments/` carry the experiment. |
| [TypeSafe JavaScript SDK](https://github.com/typesafe-ai/typesafe-sdk-js) | An official Node 20+ `@typesafe-ai/sdk` package exists, so a native TypeScript router is feasible. | This release remains Python-first; an npm package should use that SDK and have parity tests rather than wrap a Python process. |
| [MCP tool specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx) and [Python SDK migration guide](https://py.sdk.modelcontextprotocol.io/uk/migration/) | Common tool names may contain hyphens or dots, and Python MCP v2 models use snake-case attributes with camel-case wire aliases. | Preserve MCP-style tool names and accept Pydantic tool objects through alias-aware serialization. |

The prior public Python interface required callers to choose from four demo domains and treated a selected custom tool as needing the lab's placeholder argument extraction. That made general use awkward. The SDK now derives domains from caller tools, accepts a plain request string, and returns only a route decision. Mock argument preparation remains in the lab.

The Python package is installable from its Git URL now. Publishing to PyPI or npm is a separate release action and is not implied by the presence of package metadata or a build artifact. Python-first avoids maintaining two independent policy implementations before the API has real users and stable semantics. A TypeScript port can follow the same decision contract after that interface is exercised in external Python applications.
